# 8. 전원을 꺼도 남기기

> 전체 목차는 [README.md](README.md) 를 본다.

설정과 보정값을 플래시에 남긴다. 11편(VIA)이 키맵을 장치에 저장해야 하므로 그 앞에 온다.

## 자리 — 상용 영역을 피해서

이 보드는 **상용 펌웨어의 데이터가 플래시에 그대로 남아 있다.** 덤프의 e2p 헤더를
찾아 범위를 확정했다.

```
0x09FFF4   version=0x534B ('SK')  magic='HPMC'  state=0x00000000   활성 뱅크
0x0BFFF4   version=0x534B         magic='HPMC'  state=0xFFFFFFFF   예비 뱅크
```

헤더가 각 뱅크 **끝**에 있으니 상용 EEPROM 은 `0x080000 ~ 0x0C0000` = 256KB,
128KB 뱅크 2개 핑퐁이다. 그래서 우리는 그 뒤부터 쓴다.

```
0x000000 ~ 0x020000   부트로더·예약        건드리면 안 됨
0x020000 ~ 0x080000   본 펌웨어
0x080000 ~ 0x0C0000   상용 EEPROM          ★ 벤더 데이터. 건드리면 안 됨
0x0C0000   설정·보정 A    4 KB  ┐ 핑퐁
0x0C1000   설정·보정 B    4 KB  ┘
0x0C4000   VIA EEPROM          11편에서
```

`flash erase` CLI 는 `HW_FLASH_USER_BEGIN`(0x0C0000) 미만을 거부한다. 주소를 손으로
넣는 명령이라 실수로 부트로더나 벤더 데이터를 지울 수 없게 막았다.

## 실측 — 걱정하던 게 문제가 아니었다

```
cli# flash erase 0xC0000
erase 0x0C0000 : OK  (1 ms)

cli# keys save
save : OK  seq 1  (3 ms)
```

| | |
|---|---|
| 섹터 소거 (4KB) | **1 ms** |
| 저장 전체 (소거 + 536B 기록) | **2~3 ms** |

XIP 로 실행 중이라 소거·기록 동안 인터럽트를 막아야 한다. 보통 NOR 은 섹터 소거가
수십~수백 ms 라 "저장 중 USB 정지"를 어떻게 피할지가 설계의 중심이 될 뻔했는데,
이 SiP 플래시는 1ms 다. **미리 지워두기 같은 장치가 전혀 필요 없다.**

## 부팅 경로에서는 읽기만

```c
is_cfg_loaded = keysCfgLoad();   /* 읽기뿐 — XIP 라 인터럽트를 막지 않는다 */
```

쓰기는 사용자가 명시할 때만(`keys save`, `keys cal` 완료) 한다. 둘 다 못 읽으면
**기본값으로 계속 간다** — 여기서 멈추면 USB 가 안 올라와 복구가 막힌다.

이 원칙은 값비싸게 배웠다. [README 의 복구 절](README.md#6-복구)에 적어둔 대로,
"부팅 N회 실패하면 스스로 부트로더로" 라는 안전망을 넣었다가 브릭을 만들었다.
그 판단이 **초기화 아주 이른 시점에서 플래시 소거·기록**을 했고, 기록이 실패하자
조용히 리턴해 그대로 리셋 루프에 남았다.

## 레코드

```c
typedef struct {
  uint32_t magic;        /* 'KCFG' */
  uint16_t version;
  uint16_t length;       /* 버전이 올라가도 읽을 수 있게 */
  uint32_t seq;          /* 핑퐁 선택 기준. 큰 쪽이 최신 */

  uint16_t press_um;     /* 입력지점  0.01mm */
  uint16_t release_um;   /* 해제지점  0.01mm */
  uint16_t rt_um;        /* 재입력    0.01mm */
  uint8_t  sw_type_def;
  uint8_t  rsv;

  keys_key_cfg_t key[64];   /* max, min, 스위치종류, flags */

  uint32_t crc;
} keys_cfg_t;              /* 536 B */
```

**오래된 쪽 슬롯에 쓴다.** 쓰다 죽어도 다른 쪽이 남아 이전 설정으로 돌아간다.
기본값은 상용 웹툴의 "처음 사용자용" 프리셋과 같다 — 입력 1.0mm / 해제 0.5mm /
재입력 0.5mm.

## 스위치 종류표는 펌웨어에

보정을 안 해도 mm 환산이 되도록 **공칭 스트로크**를 상수로 갖고 있고, 보정하면
키별 실측이 우선한다. 상용도 같은 구조다 — `common_arr` 블록에 키마다 종류 인덱스가
있고(전 키 3), 설정은 mm 단위다.

## `keys cal`

기준값(무압)은 러닝 최대값이 늘 추적하지만 **바닥값은 실제로 끝까지 눌러야만** 알 수
있다. 둘이 있어야 눌린 깊이를 mm 로 환산할 수 있다.

```
cli# keys cal
키보드에서   [Ctrl + Enter] 여기까지 저장하고 끝
             [Ctrl + ESC]   취소 (저장하지 않음)

  [#][#][#][#][#][#][#][#][#][#][#][#][#][####] [ ][ ]
  [##][#][#][#][#][#][#][#][#][#][#][#][#][###]
  [###][#][#][#][#][#][#][#][#][#][#][#][#####]
  [####][#][#][#][#][#][#][#][#][#][#][####][#]
  [##][#][###][###################][##][#][###]
  61 / 63 완료

보정 61 / 63 저장  (2개는 스위치가 없거나 덜 눌림 — 공칭값 유지)
save : OK  seq 3
빠진 자리 : 1,5 3,5
```

진행 상황을 **실제 배치로** 보여준다. 8×8 격자로는 어느 키가 남았는지 알 수 없다.
그래서 `keys layout` 의 렌더러를 `mark()` 콜백을 받는 헬퍼로 분리해 같이 쓴다.

## 겪은 함정

### ① 측정하려고 누른 키가 터미널에 입력된다

전 키를 눌러야 하는 매핑·보정에서는 **측정 자체가 불가능했다.** CLI 가 글자로 뒤덮이고
끊긴다. `cliKeys()` 진입에서 리포트를 막고 나갈 때 푼다.

막을 때 **빈 리포트를 한 번 보내는 게 중요하다.** 그냥 건너뛰면 직전에 눌려 있던
키가 호스트에 눌린 채로 남는다.

### ② "전부 끝나야 저장"으로 막으면 영영 저장 못 한다

레이아웃에는 레이아웃 옵션 소켓(스플릿 백스페이스 등)이 다 들어 있지만 실제로는
그중 하나만 끼운다. 2U 백스페이스 하나만 쓰면 **61/63 이 최대**다.

끝난 키만 보정됨으로 표시하고 나머지는 공칭값을 계속 쓴다. **빠진 자리를 찍어주므로**
예상과 다르면 장착이나 배선을 의심할 수 있다 — 실제로 `1,5` 와 `3,5` 가 나와
스플릿 백스페이스 소켓임이 확인됐다.

### ③ 종료 조합을 누르면 그 키들이 보정된다

`Ctrl + ESC` 하나로 "끝내기"를 묶었더니, **취소하려고 눌러도 두 키짜리 보정이
61개짜리를 덮어썼다.** 저장과 취소를 갈랐다.

```
Ctrl + Enter   여기까지 저장
Ctrl + ESC     취소 — 기존 보정 유지
```

## 검증

```
cli# keys cfg
loaded      : 1  (seq 3)          <- 재부팅 후에도 유지
calibrated  : 61 / 64 키

키별 스트로크 (보정된 것만, '-' 은 미보정)
       ch0   ch1   ch2   ch3   ch4   ch5   ch6   ch7
  s0     853   829   848   832   853   883     -   840
  ...
  s7     850   824   864   799   825   882   812   801

  최소 757, 최대 893, 평균 836  (편차 16%)
```

**편차 16% 가 13편의 근거다.** 보정 없이 공칭값만 쓰면 액추에이션 1.0mm 가 키마다
0.94~1.07mm 로 흔들린다. 래피드 트리거는 0.1mm 단위를 다루므로 이 정도 편차를
무시할 수 없다 — 보정은 선택이 아니라 권장이다.

## 상용과 비교

상용 펌웨어는 **HPM SDK 의 `eeprom_emulation` 컴포넌트**를 쓴다. 블록 키-값 저장소이고
바이너리에 뱅크 이름이 그대로 남아 있다.

| 블록 | 개수 | 크기 |
|---|---|---|
| `flash_common_bank` | 1 | 4 KB |
| `flash_common_arr_bank` | 1 | 4 KB |
| `flash_ap_rt_bank` | **4 프로파일** | 16 KB |
| `flash_led_bank` | 4 | 16 KB |
| `flash_keycode_bank` | 4 | 16 KB |
| `flash_keycode_bank_2` | 4 | 16 KB |

논리 72KB, 프로파일 4개, 블록 하나가 4KB 고정이다. `ap_rt` 는 `+0x200` 부터
128슬롯 × uint16 배열 7개(값 100·100·400·600·10·1·0), `common_arr` 은 128슬롯 전부
`3` — 키별 스위치 종류 인덱스다.

> **보정 블록은 없었다.** 한때 "상용은 보정을 저장하지 않는다"고 판단했는데 오독이었다.
> e2p 는 쓴 적 있는 블록만 존재하고, 그 덤프는 **한 번도 보정하지 않은 보드**였을
> 뿐이다. 웹툴에는 자동/수동 보정 토글이 있다.

11편에서 VIA 를 붙일 때 이 컴포넌트를 그대로 쓸 예정이다. `E2P_ATTR = ATTR_RAMFUNC`
가 기본이라 코드가 RAM 에서 돌아 XIP 정지 문제가 없다.
