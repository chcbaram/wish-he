# 하드웨어 사양

이 펌웨어가 전제하는 보드 사양이다. 구현 중 필요한 값은 전부 여기 모아둔다.

---

## 1. MCU · 전원 · 클럭

| 항목 | 값 |
|---|---|
| MCU | HPM5361 (LQFP100), RISC-V |
| CPU 클럭 | **400MHz** — PLL0CLK2 직결 |
| AXI/AHB | 133MHz |
| 코어 전원 | **외부 공급** |

> ★ **내장 DCDC 전압을 설정하면 안 된다.** `pcfg_dcdc_set_voltage()` 를 호출하면
> `VOLT` 에는 값이 들어가고 `MODE` 도 `001`(basic) 인데 `DCDC_MODE.READY`(bit28) 가
> 영영 서지 않아 `pcfg_dcdc_is_stable()` 에서 무한 대기한다.
> SDK 원본 주석이 경고하는 그대로다.

24MHz 크리스털이 필수다. LQFP100 은 내부 RC 부팅을 지원하지 않는다.

## 2. 플래시

**1MB SiP 내장 NOR** — 패키지 안에 있어 떼어낼 부품이 없다. XPI0 **2번 핀그룹
(PX00~PX07)** 에 붙어 있다.

```c
/* nor_cfg_option — 부트로더가 이미 갖고 있으므로 앱은 만들지 않는다 */
{ 0xfcf90002, 0x00000006, 0x00001000, 0x00000000 }
     header      120MHz      핀그룹 2
```

> `header` 하위 4비트가 **뒤따르는 옵션 워드 개수**다. ROM API 를 직접 부를 때
> `0xFCF90001` 로 주면 `option1`(핀그룹)이 무시돼 기록이 실패한다.

### 메모리 배치

| 오프셋 | 실행 주소 | 내용 | 우리가 쓰는가 |
|---|---|---|---|
| `0x000400` | `0x80000400` | nor_cfg_option (16 B) | ✗ 보존 |
| `0x001000` | `0x80001000` | 부트 헤더 (144 B) | ✗ 보존 |
| `0x003000` | `0x80003000` | **부트로더** (약 76 KB) | ✗ 보존 |
| `0x01D000` | `0x8001D000` | **업데이트 플래그** (4 B) | 쓰기 |
| `0x01E000` | `0x8001E000` | 시리얼 문자열 (16 B) | ✗ 보존 |
| `0x020000` | `0x80020000` | **본 펌웨어** (384 KB 할당) | ✓ |
| `0x080000` | `0x80080000` | EEPROM 에뮬레이션 | ✗ 보존 |

링커 `FLASH` 를 `ORIGIN=0x80020000 / LENGTH=0x60000` 으로 묶으면 EEPROM 을
침범하지 않는다.

## 3. 부트로더 인터페이스

부트로더가 앱으로 넘어오는 조건은 **세 가지가 모두 참**일 때다.

| # | 조건 |
|---|---|
| 1 | `0x80020000` 의 4바이트가 `48 50 4D 0A` (`"HPM\n"`) |
| 2 | **PA09 가 HIGH** (10회 샘플 중 7회 이상) |
| 3 | `0x8001D000` 워드가 `0xFFFFFFFF` (소거 상태) |

진입점은 `0x80020004` — 매직 바로 다음이다.

하나라도 어긋나면 **USB 업데이트 모드**로 남는다. 즉 세 가지가 그대로 복구 경로다.

### 업데이트 모드 USB

| IF | usage page | 용도 |
|---|---|---|
| 0 | `0x0001/0x06` | 부트 키보드 |
| 1 | `0xFF60` | VIA 계열 |
| 2 | `0x0001`, `0x000C` | 마우스 · 컨슈머 · 시스템 |
| **3** | **`0xFF53`** | **업데이트 채널** (64 B 리포트) |

프로토콜은 [09-iap-updater.md](09-iap-updater.md) 를 본다.

### ★ 인계 상태 — 부트로더는 주변장치를 켜둔 채 넘긴다

앱이 `mstatus.MIE` 를 여는 순간 등록되지 않은 벡터로 점프해 죽는다. 앱 초기화에서
반드시 정리해야 한다.

| 남는 것 | 증상 | 처리 |
|---|---|---|
| `mie` 비트 | — | `write_csr(CSR_MIE, 0)` |
| PLIC enable | — | 전 채널 `intc_m_disable_irq()` |
| **PLIC pending** (GPTMR1) | `default_irq_handler` 무한루프 | **claim/complete 로 배수** |
| SPI1 active (LED 전송) | 첫 LED 전송이 busy 로 거부 | 유휴 대기 + `spi_poll_reset_complete()` |
| HDMA 채널 | — | `dma_abort_channel()` |

상세는 [01-boot-on-iap.md](01-boot-on-iap.md).

## 4. 핀맵

### 키 스캔 — ADC + 아날로그 MUX

```
PB00 ~ PB03   ADC0 시퀀스 4채널
PB04 ~ PB07   ADC1 시퀀스 4채널     -> 동시 8채널
PY00 ~ PY02   MUX 주소 3비트        -> 8스텝

              8채널 x 8스텝 = 64키
```

- `PB00~PB15` 는 전부 아날로그로 잡히지만 **실제 시퀀스에 등록되는 것은 8개**다
- MUX 주소는 `DO[PY].VALUE` 에 **포트 전체를 한 번에** 쓴다 (비트별 SET/CLEAR 아님)
- 주소 순서는 그레이 코드 `[6, 7, 5, 4, 0, 1, 3, 2]` — 스텝당 1비트만 바뀌어
  크로스토크가 적다
- `PY` 패드는 IOC 뿐 아니라 **PIOC 도 함께** 설정해야 SoC 기능이 연결된다

### RGB LED

| 항목 | 값 |
|---|---|
| 데이터 핀 | **PA29 = SPI1.MOSI (ALT5)** |
| 구동 | SPI 8MHz + HDMA — SPI 1바이트 = WS2812 1비트 |
| 개수 | **83**, GRB 순서 |

핀 먹싱은 부트로더가 이미 해두지만 앱에서 다시 잡는다.

### 그 밖

| 핀 | 용도 |
|---|---|
| **PA04~PA08** | JTAG (TDO/TDI/TCK/TMS/TRST) — **앱에서 건드리지 말 것** |
| **PA09** | 부트 진입 스트랩. LOW 로 잡고 전원 인가하면 업데이트 모드 (보드상 위치 미확인) |
| PA24 / PA25 | USB0 DM / DP |
| PA00 / PA01 | UART0 — **이 보드에는 헤더가 없다** |
| PA11 / PA12 | 정적 출력, 용도 미상 (초기 H / L) |

> JTAG 핀을 GPIO 로 리먹싱하면 디버거가 붙지 않는다. 이 펌웨어는 PA04~PA08 을
> 전혀 건드리지 않으므로 언제든 JTAG 로 접근할 수 있다.

## 5. 전류 예산

USB 선언은 500mA. WS2812 는 채널당 풀스케일 약 20mA, LED 1개 흰색이면 약 60mA다.

```
83개 흰색 v  ->  v × 19.5 mA
83개 단색 v  ->  v ×  6.5 mA
```

MCU·USB·홀센서를 빼면 LED 몫은 대략 200~300mA. **전체 흰색은 v ≈ 10~15,
전체 단색은 v ≈ 30~45** 가 상한이다. 프레임 전류 합산 리미터가 필요하다.
